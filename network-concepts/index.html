TCP/IP Architecture

TCP/IP is the practical protocol suite that powers modern networks and the internet. Unlike OSI, which is a conceptual model, TCP/IP is used in real-world communication stacks. It condenses networking into four layers.

Encapsulation and Decapsulation

This is one of the most fundamental networking concepts. As data moves down the sender's protocol stack, each layer wraps the previous layer's output with its own header (and at Layer 2, a trailer). The result grows progressively larger, like nested envelopes. On the receiving side, each layer reads and strips its own header, passing the payload upward until the original application data is delivered.

Postal analogy: Think of it like mailing a letter. The data is the letter. The Transport layer puts it in an envelope with port numbers. The Network layer adds a shipping label with IP addresses. The Data Link layer places it in a delivery pouch with MAC addresses and a seal (FCS). The Physical layer converts it to electrical signals on the wire. The receiver opens each layer in reverse.

End-to-End Packet Flow

From URL to response: the full network journey. The diagram traces a request from a user's browser, through the local network and the routers in between, to a remote server and back, layer by layer and hop by hop.

Text version of this diagram

Portrait diagram of the eight steps from typing a URL to seeing the page, in order, each marked with its OSI layer. Scenario: a laptop on a home or office network opens https://example.com/ for the first time, using IPv4 behind NAT and TLS 1.3 over TCP.

  1. Layer 7, URL parsed and caches checked. The browser splits the URL into scheme (https), host (example.com) and path, then checks its caches. A cached DNS answer or an open connection lets it skip steps below.
  2. DNS, name to IP address. First, at layer 2, the next hop's MAC address: no packet can leave without a frame, and a frame needs the MAC address of the next hop: the DNS resolver if it is on this subnet, otherwise the default gateway. ARP (IPv6: Neighbour Discovery) finds it. The answer is cached, so this repeats only when the cache has no entry. The host broadcasts an ARP request asking who has 192.168.1.1 and receives an ARP reply with the MAC address. Then, at layer 7, the DNS query: the host asks its recursive resolver for the address of example.com, usually over UDP port 53. The resolver returns an A record (IPv4) or an AAAA record (IPv6). The query asks for example.com type A and the answer is 198.51.100.20.
  3. Layer 4, TCP three-way handshake. The host opens a TCP connection to port 443 on the server. Ports are layer 4 addresses: they identify the service, not the machine. One round trip. The messages are SYN, SYN-ACK, ACK.
  4. Layer 6, TLS 1.3 handshake. One round trip. The server proves its identity with a certificate and both sides derive the session keys. Everything after ServerHello is encrypted. The messages are ClientHello with key share; ServerHello with key share, certificate and Finished; then the client's Finished.
  5. Layer 7, HTTP request. The browser sends GET / for example.com inside the TLS session. Each layer below wraps it, so one frame on the wire is, in order: Ethernet header (layer 2), IP header (layer 3), TCP header (layer 4), the TLS record carrying the encrypted HTTP request (layers 6 and 7), and the frame check sequence (layer 2), sent as bits at layer 1.
  6. Layers 3 and 2, every packet is routed hop by hop. This is true of every packet in the steps above, in both directions. One packet is followed across three links: your host to the home router with NAT (link 1), on to the internet routers (link 2), and on to the server (link 3). New frame on every link: each router removes the frame and builds a new one, so the source and destination MAC addresses change (MAC pair A on link 1, B on link 2, C on link 3). TTL drops by 1 at each router and the IPv4 header checksum is recomputed (TTL 64 on link 1, 63 on link 2, 62 and falling on link 3); in IPv6 the Hop Limit drops and there is no header checksum. NAT at the network edge rewrites the source address and source port, private to public: 192.168.1.10 port 51000 on link 1 becomes 203.0.113.5 port 40001 on links 2 and 3. Not changed by routers: the TCP payload; the TLS-encrypted HTTP data arrives exactly as it was sent.
  7. Layer 7, server responds. The server (often a load balancer or CDN edge in front of it) decrypts the request and returns status 200 with headers and the HTML. The reply is routed back hop by hop, and the NAT table maps it to your host.
  8. Layer 7, browser renders the page. The browser parses the HTML into the DOM, fetches the CSS, scripts and images it names (reusing the connection where it can), then runs style, layout and paint.

Note, common alternative HTTP/3. HTTP/3 runs over QUIC, which uses UDP (usually port 443) instead of TCP. QUIC builds TLS 1.3 into its own handshake, so steps 3 and 4 become a single round trip. Every other step is the same.

The diagram states that it was checked against RFC 791, 826, 1035, 3022, 4861, 8200, 8446, 9000, 9114 and 9293, and MDN Web Docs.

Key insight: At the endpoints (client and server), all 7 OSI layers are involved. A router works at L1 to L3: it removes the L2 frame, reads the destination IP address, decrements the TTL, recalculates the IPv4 header checksum and builds a new L2 frame for the next hop. A switch works at L1 and L2 and forwards the frame as it is. So the frame is replaced at every routed hop, while the IP addresses and the TCP or UDP segment normally stay the same from end to end. The exceptions matter in security work: NAT rewrites addresses and ports, and proxies, load balancers and TLS-inspecting firewalls end the connection and start a new one. With HTTP/3 the same web traffic travels as QUIC over UDP port 443, so a rule or a sensor that watches only TCP 443 will miss it.

Core Protocols of TCP/IP Architecture

These protocols form the working language of modern networks. Expand each area for a fast, practical explanation.

HTTP / HTTPS
HTTP transfers web content. HTTPS is HTTP protected with TLS for confidentiality, integrity, and server authentication. It is foundational for websites, APIs, portals, SaaS platforms, and enterprise web applications. HTTP/1.1 and HTTP/2 run over TCP; HTTP/3 runs over QUIC, which is carried in UDP.
DNS
The Domain Name System resolves names such as example.com into IP addresses. Without DNS, users would need to remember numeric IP addresses. It is critical, and therefore a common target for abuse, poisoning, tunnelling, and redirection.

Record types: A, AAAA, CNAME, MX, NS, TXT, PTR, SOA

DNS uses port 53: UDP for most queries, TCP for large answers and zone transfers. DNSSEC adds signatures so that a resolver can check an answer is authentic; it does not encrypt the traffic.

SMTP / IMAP / POP3
SMTP is used to send email. IMAP and POP3 are used to retrieve email, with IMAP allowing richer synchronisation across devices. Security depends heavily on TLS, authentication, and anti-phishing controls.
FTP / SFTP / SSH
FTP moves files but is insecure in plaintext. SFTP runs over SSH and provides secure file transfer. SSH itself enables encrypted remote administration and secure command-line access.
DHCP
Dynamic Host Configuration Protocol automatically assigns IP addresses and other network settings such as default gateway and DNS servers to clients joining a network.
SNMP
Simple Network Management Protocol is used to monitor and manage network devices such as routers, switches, and servers. SNMPv3 adds encryption and authentication. It operates over UDP ports 161 (queries) and 162 (traps).
LDAP / LDAPS
Lightweight Directory Access Protocol is used to query and manage directory services such as Active Directory. LDAPS adds TLS encryption. Commonly used for authentication, authorisation, and user/group management in enterprise environments.
TCP
Transmission Control Protocol is connection-oriented and reliable. It uses sequence numbers, acknowledgements, retransmissions, and flow control. It is used where correctness matters, such as web sessions, file transfer, and email transport.
UDP
User Datagram Protocol is connectionless and lightweight. It does not guarantee delivery, ordering, or retransmission. It is used where speed and low overhead matter, such as streaming, VoIP, DNS queries, and some real-time applications.
QUIC
QUIC is a newer transport protocol that runs on top of UDP. It builds in the TLS 1.3 handshake, carries several independent streams in one connection, and provides its own reliable delivery and congestion control. HTTP/3 uses it. Because QUIC is encrypted from the handshake onwards and normally uses UDP port 443, inspection tools that only understand TLS over TCP cannot see into it.
Ports and Sockets
Ports identify logical services on a host, while sockets represent communication endpoints. Firewalls and transport-layer controls often allow or block traffic based on port and protocol combinations.
IP (IPv4 / IPv6)
Internet Protocol handles addressing and routing across networks. IPv4 is still used almost everywhere, while IPv6 provides a vastly larger address space and a simpler fixed header.
ICMP
Internet Control Message Protocol supports diagnostics and control messaging, such as ping and path testing. It is useful operationally but can also be abused for scanning and flood activity.
IPsec
IPsec protects IP traffic with encryption and authentication, often used in VPNs and secure site-to-site communication at the network layer.
NAT
Network Address Translation rewrites IP addresses, and usually port numbers, as packets cross a boundary. Its most common use lets many devices with private (RFC 1918) addresses share one public IPv4 address. NAT hides internal addressing, but it is not a firewall: it does not inspect traffic. It also means that the address a server logs is the shared public one, so tracing a connection back to a single device needs the logs of the NAT device.
Routing Protocols
Protocols such as OSPF, BGP, and EIGRP determine how routes are learned and exchanged. They are essential for enterprise and internet routing and therefore high-impact from a resilience and trust perspective. BGP does not itself check that a network is entitled to announce a prefix; RPKI route origin validation adds that check.
Ethernet
Ethernet is the dominant wired LAN technology. It defines frame structures, MAC addressing behaviour, and media access characteristics for local networks.
Wi-Fi
Wi-Fi provides wireless LAN connectivity. Security depends on encryption, authentication, segmentation, and strong wireless design practices.
ARP
Address Resolution Protocol maps IPv4 addresses to MAC addresses inside a local network. Because ARP lacks strong native trust controls, it is a common source of spoofing and poisoning attacks.
MAC Addressing
MAC addresses identify network interfaces at Layer 2. Switching and access control decisions at the local network layer often depend on them.

Communication Model

Connection-Oriented vs Connectionless

Connection-Oriented (TCP, SCTP)

TCP sets up a session with a three-way handshake; SCTP uses a four-way handshake. Both deliver data reliably and in order by detecting loss and retransmitting. That is not a guarantee: if the path fails, the connection breaks and the application is told. TCP adds flow control with a sliding window and closes gracefully with FIN and ACK. Use: web, email, file transfer, APIs.

Connectionless (UDP, ICMP)

No session setup: data is sent immediately. No delivery guarantee, ordering, or retransmission. The UDP header is only 8 bytes. Use: DNS, VoIP, streaming, gaming, NTP.

Security Control Model

Stateful vs Stateless Controls

Stateless

Evaluates each packet independently against rules. No memory of prior traffic. Examples: simple packet-filter ACLs on routers. Faster processing but cannot distinguish legitimate replies from unsolicited inbound traffic.

Stateful

Maintains a connection state table tracking active sessions. Understands whether a packet belongs to an established session or is unexpected. Examples: stateful firewalls, NGFWs. Allows return traffic automatically; detects out-of-state packets.

How they connect: Connection-oriented protocols (TCP) work naturally with stateful controls because both track session state. Connectionless protocols (UDP) are harder for stateful devices to inspect: they typically use timeouts and heuristics to create pseudo-state entries.

Core Networking Devices by Function

Device type mapped to operational role and primary OSI layer.

Router

Forwards packets between networks and makes routing decisions based on IP addressing.

Switch

Connects devices within the same local network and forwards frames using MAC addresses.

Firewall

Filters traffic based on rules. It may work at Layer 3, Layer 4, or Layer 7 depending on design.

Load Balancer

Distributes traffic across multiple servers for performance and availability.

IDS / IPS

Detects or blocks suspicious traffic patterns and known malicious signatures or behaviours.

DNS Server

Translates domain names to IP addresses so systems can locate one another.

Proxy Server

Acts as an intermediary between clients and servers, providing caching, filtering, access control, and anonymity.

WAF

Web Application Firewall inspects HTTP/HTTPS traffic at Layer 7 to block SQL injection, XSS, and other application-layer attacks.

VPN Gateway

Terminates encrypted VPN tunnels, providing secure remote access or site-to-site connectivity over untrusted networks.

SIEM

Security Information and Event Management platform that aggregates logs, correlates events, and provides alerting for security operations.

Threats, Threat Actors, Vulnerabilities, Attacks, Controls, Attack Vectors and Mitigations

These terms are related but not interchangeable. Understanding the distinction is essential for risk assessment, incident response, control design, and security strategy.

Threat

Potential cause of harm

A threat is anything capable of causing damage by exploiting a weakness. It may be human, technical, environmental, or operational.

MalwareInsider misusePower failure
Threat Actor

Entity that can execute a threat

Threat actors include cybercriminals, nation-state operators, insiders, hacktivists, script kiddies, and malicious competitors.

CybercriminalInsiderAPT
Vulnerability

Exploitable weakness in a system

A vulnerability is a flaw in software, configuration, process, or design that can be exploited by a threat actor. A vulnerability alone is not a risk: see Risk below. Common examples include unpatched software, misconfigured services, default credentials, and insecure code.

Unpatched CVEMisconfigurationWeak password
Attack Vector

Path used to reach the target

This is the route or mechanism used to carry out the attack. Examples include email, exposed ports, weak VPNs, vulnerable web forms, infected USB devices, and misconfigured APIs.

Attack

Actual exploitation attempt

An attack is the event where a threat actor takes action to compromise confidentiality, integrity, or availability.

PhishingDDoSARP Poisoning
Control

Safeguard that prevents, detects, corrects or deters

Controls may be preventive, detective, corrective, deterrent, or compensating. They can be administrative, technical, or physical.

FirewallMFAEDRSIEM
Mitigation

Action used to reduce likelihood or impact

Mitigations are practical risk-reduction measures such as patching, segmentation, secure configuration, rate limiting, user awareness, backups, and incident playbooks.

Risk

Likelihood and impact, not threat plus vulnerability

Risk is not the sum of a threat and a vulnerability. NIST SP 800-30 Rev. 1 (section 2.3) defines risk as a measure of the extent to which an entity is threatened by a potential circumstance or event, typically a function of the adverse impact if the event occurs and the likelihood that it occurs. In practice, ask two questions about each asset: how likely is it that a threat will exploit this vulnerability, and how much harm would follow? An unpatched server that nothing can reach, or that holds nothing of value, has a real vulnerability and is still a low risk.

  2. Threat. Any circumstance or event with the potential to harm an organisation, its assets or its people. Example: a finance mailbox could be taken over and used for payment fraud. Link 2 targets link 3.
  3. Vulnerability. A weakness in a system, procedure or control that a threat could exploit. Example: sign-in needs only a password (no MFA), and staff cannot spot a phishing email. Link 3 is used by link 4.
  4. Exploit. The technique or code that takes advantage of a vulnerability. Example: a phishing email and a fake sign-in page capture the clerk's password. Link 4 enables link 5.
  5. Attack or incident. The malicious act itself, which jeopardises confidentiality, integrity or availability. Example: the attacker signs in as the clerk and emails customers new bank details. Link 5 results in link 6.
  6. Impact. The harm to operations, assets and people that results: the business consequence. Example: a customer pays ₹18 lakh into the fraudster's account. Money and trust are lost.

A column beside the chain shows where controls act. Links 1 and 2, the threat actor and the threat, are largely outside your control. Prevent acts on links 3 and 4: close the weakness and block the method (phishing-resistant MFA, email filtering, staff training). Detect acts on link 5: notice the attack as it happens (alerts on unusual sign-ins and on new mailbox forwarding rules). Respond acts on link 5: contain it (revoke the sessions, reset the password, warn customers and the bank). Recover acts on link 6: restore and make good (recall the payment through the bank, restore the mailbox, fix the gap that was used). A control is a safeguard or countermeasure. The earlier it breaks the chain, the smaller the impact.

Defence in Depth: Layered Security Architecture

No single control can protect an entire network. Defence in depth is a strategy that layers multiple, overlapping security controls so that if one layer fails, the next layer catches the threat. It is one of the basic principles of security architecture.

Core principle: Assume every individual control can be bypassed. Defence in depth means an attacker must defeat multiple independent barriers (across identity, endpoint, network, application, data, and physical layers) before achieving their objective. Each layer buys time, generates alerts, and limits blast radius.

Each card below ends with the NIST SP 800-53 Rev. 5 control families that cover it.

Read one line with care: the image says layered controls reduce the chance of a successful attack "exponentially". That is true only if the controls fail independently of one another, and real controls often do not: one stolen administrator credential can defeat several layers at once. Treat it as an argument for layering, not as a measured result.

Why layering matters

Single control failure ≠ total compromise

Consider a real-world attack path: an attacker sends a phishing email (bypasses perimeter), a user clicks (endpoint compromised), the malware moves laterally (network segmentation blocks it), or exfiltrates data (DLP detects and blocks). Each layer independently resists the attack even if the previous one fails.

  • Preventive controls: stop attacks before they succeed (firewalls, MFA, encryption)
  • Detective controls: identify attacks in progress (SIEM, IDS, log monitoring)
  • Corrective controls: limit damage and restore operations (incident response, backups, patching)
  • Deterrent controls: discourage attackers from attempting (security policies, legal warnings, visible cameras)
  • Compensating controls: alternative safeguards when primary controls are not feasible
Zero Trust Architecture (NIST SP 800-207)

No trust from network location alone

Zero Trust removes the idea that anything inside the network perimeter can be trusted. NIST SP 800-207 sets out seven tenets. In short: every data source and service is a resource; all communication is secured wherever it comes from; access is granted per session, with the least privilege needed; access decisions follow dynamic policy that looks at identity, device state and context; the organisation monitors the security posture of its assets; authentication and authorisation are enforced before access and re-evaluated; and it collects information about assets and traffic to keep improving. Zero Trust complements Defence in Depth: layered defence provides several barriers, and Zero Trust makes sure that nothing is trusted automatically even inside them.

Per-session Access Least Privilege Dynamic Policy Device Posture Continuous Monitoring

Two phrases often credited to NIST are not in SP 800-207. "Never trust, always verify" is an industry slogan, and the three principles "verify explicitly, use least privilege access, assume breach" are Microsoft's summary of Zero Trust (Microsoft now words the third as "assume compromise"). They are useful shorthand; name the right source when you use them.

Practical Troubleshooting by Layer

This is how engineers isolate faults quickly in the real world: start at the right layer instead of guessing randomly.

Layer 1: Physical

Check cable, power, interface status, optics, radio signal, physical damage.

Layer 2: Data Link

Check MAC learning, switch ports, VLAN membership, ARP resolution, NAC policy.

Layer 3: Network

Check IP address, subnet mask, gateway, route table, ICMP reachability.

Layer 4: Transport

Check open ports, firewall policy, stateful inspection, TCP handshake issues.

Layer 5/6: Session / Presentation

Check session state and token validity, TLS negotiation failures, certificate errors, encoding mismatches, and content-type issues. In practice, these symptoms typically surface at Layer 7 but originate from session or presentation logic.

Layer 7: Application

Check application service health, DNS records, certificates, authentication, API response.

Mindset

Always map the symptom to the likely layer first. It reduces noise and speeds up root-cause analysis.

802.1XAn IEEE standard for port-based network access control. A device must authenticate before the switch port or wireless connection is opened, normally with EAP checked by a RADIUS server. Used on wired and wireless networks.
ACLAccess Control List. A set of rules on a router, switch or firewall that permits or denies traffic by IP address, port or protocol.

BandwidthThe maximum data transfer capacity of a network link, usually measured in Mbps or Gbps.
BGPBorder Gateway Protocol. The routing protocol used to exchange routes between autonomous systems on the internet, over TCP port 179. It does not itself check that a network is entitled to announce a prefix: see RPKI.

CSPContent Security Policy. An HTTP response header that tells the browser which sources of script and other content a page may load. A defence against XSS.
CSRFCross-Site Request Forgery. An attack that makes a signed-in user's browser send an unwanted request to a site that trusts it. Mitigated with anti-CSRF tokens and SameSite cookies.
DAIDynamic ARP Inspection. A switch security feature that checks ARP packets against a trusted table of IP-to-MAC bindings to prevent ARP poisoning.
DDoSDistributed Denial of Service. An attack that floods a target with traffic from many sources at once, so that legitimate users cannot reach it. Mitigated with rate limiting, CDNs and scrubbing services.
DecapsulationThe reverse of encapsulation: the receiving host reads and strips each header in turn, from Layer 1 up to Layer 7, until the original application data is delivered. See Encapsulation.
Default GatewayThe router address a device uses to reach destinations outside its own subnet.
DHCPDynamic Host Configuration Protocol. Automatically gives a device its IP address, subnet mask, default gateway and DNS servers when it joins a network. UDP ports 67 and 68.
DLPData Loss Prevention. Tools and policies that detect and prevent unauthorised transmission of sensitive data outside the organisation.
DMZDemilitarised Zone. A network segment between the internal network and the internet that hosts public-facing services while keeping them apart from internal systems.
DNSDomain Name System. Translates domain names such as example.com into IP addresses. Uses port 53, over UDP for most queries and over TCP for large answers and zone transfers. See Core Protocols.
DNS ServerA server that answers DNS queries. A recursive resolver looks names up on behalf of clients; an authoritative server holds the records for a zone.
DNSSECDNS Security Extensions. Adds digital signatures to DNS records so that a resolver can check that an answer really comes from the zone owner and has not been altered. It does not encrypt DNS traffic.
EDR / XDREndpoint Detection and Response / Extended Detection and Response. Tools that monitor endpoints (or, for XDR, several sources of telemetry) for threats and support rapid investigation and containment.
EIGRPEnhanced Interior Gateway Routing Protocol. A Cisco-developed advanced distance-vector routing protocol used inside enterprise networks.
EncapsulationThe process in which each protocol layer wraps the previous layer's output with its own header (and, at Layer 2, a trailer) before transmission. See Encapsulation.
EthernetThe dominant wired LAN technology. It defines the frame format, MAC addressing and media access for local networks, at Layers 1 and 2.
FCSFrame Check Sequence. A 4-byte error-detection value added to the end of an Ethernet frame so that the receiver can detect corruption.
FirewallA network security device that filters traffic according to rules. It may work at Layer 3 (packet filter), Layer 4 (stateful) or Layer 7 (application firewall, WAF). See Devices.
FrameThe Protocol Data Unit at Layer 2. It contains a header (source and destination MAC addresses), the payload and an FCS trailer.
FTP / SFTPFile Transfer Protocol sends files and passwords in plaintext (TCP port 21 for control, 20 for data). SFTP, the SSH File Transfer Protocol, is a different protocol that runs inside SSH on TCP port 22.
Full DuplexA communication mode in which data can be sent and received at the same time on the same link.
GatewayA device or system that connects two different networks or protocol domains. The default gateway is normally a router.
Half DuplexA communication mode in which data can be sent or received, but not both at once, so devices take turns. Used by old Ethernet hubs and some wireless links.
HSTSHTTP Strict Transport Security. A response header (Strict-Transport-Security) with which a site tells browsers to reach it only over HTTPS. A defence against SSL stripping.
HTTP / HTTPSHyperText Transfer Protocol, and HTTP over TLS. The foundation of web communication. HTTPS adds encryption, integrity and server authentication. See Core Protocols.
HubA Layer 1 device that repeats an incoming signal out of every other port. It does not read MAC addresses. Replaced by switches in modern networks.
ICMPInternet Control Message Protocol. Used for diagnostics (ping, traceroute) and error reporting at Layer 3. It can be abused for scanning and floods.
IDS / IPSIntrusion Detection System / Intrusion Prevention System. An IDS monitors traffic and raises alerts on suspicious activity; an IPS also blocks it.
IMAPInternet Message Access Protocol. Retrieves email while keeping messages on the server, synchronised across devices. TCP port 143, or 993 over TLS.
IP AddressA logical address assigned to a device at Layer 3. IPv4 addresses are 32 bits long; IPv6 addresses are 128 bits.
IPsecInternet Protocol Security. A suite of protocols that encrypts and authenticates IP traffic. Commonly used in VPNs for site-to-site and remote access tunnels.
JitterVariation in packet arrival times. High jitter degrades real-time applications such as VoIP and video conferencing.
KerberosA network authentication protocol in which a Key Distribution Centre (KDC) issues tickets that prove identity to services. In a Windows domain the KDC runs on the domain controllers. Port 88, over UDP and TCP.
LatencyThe delay between sending a packet and receiving a response, measured in milliseconds. Lower latency means a faster response.
LDAP / LDAPSLightweight Directory Access Protocol. Queries and manages directory services such as Active Directory. LDAPS is LDAP over TLS. TCP ports 389 and 636.
Load BalancerA device or service that distributes incoming traffic across several servers to improve performance, availability and fault tolerance. It may work at Layer 4 or Layer 7.
MAC AddressMedia Access Control address. A 48-bit identifier assigned to a network interface and used for communication on the local network at Layer 2.
MalwareMalicious software designed to damage, disrupt or gain unauthorised access to systems. Includes viruses, worms, trojans, ransomware, spyware and rootkits.
MFAMulti-Factor Authentication. Requires two or more verification factors (something you know, something you have, something you are) before granting access.
MitigationAn action that reduces the likelihood or the impact of an attack, such as patching, segmentation or backups. See Threats and Controls.
MTUMaximum Transmission Unit. The largest packet, in bytes, that a link can carry without fragmentation. The standard Ethernet MTU is 1500 bytes.
MulticastA transmission sent to a group of interested receivers, not to every device (broadcast) or to one device (unicast). Used for streaming, routing updates and IPv6 neighbour discovery.
NACNetwork Access Control. Enforces security policy on a device before it is allowed onto the network. Often built on 802.1X.
NATNetwork Address Translation. Rewrites IP addresses, and usually ports, at a network boundary, most often so that many devices with private addresses can share one public IPv4 address. It is not a firewall. See Core Protocols.
NetBIOSNetwork Basic Input/Output System. A legacy session-layer API and naming service used for file sharing and name resolution on Windows networks. Largely replaced by DNS and by SMB running directly over TCP.
NGFWNext-Generation Firewall. A vendor term, not a standard: a stateful firewall that also identifies applications and users and includes intrusion prevention.
NICNetwork Interface Card. The hardware that connects a device to a network. It works at Layer 1 (signals) and Layer 2 (MAC addressing).
NTPNetwork Time Protocol. Synchronises clocks across networked devices, which log correlation and forensics depend on. UDP port 123.
OSI ModelOpen Systems Interconnection model. A 7-layer conceptual framework for network communication: Physical, Data Link, Network, Transport, Session, Presentation, Application. See OSI Architecture.
OSPFOpen Shortest Path First. A link-state interior routing protocol that calculates the shortest path with Dijkstra's algorithm.
PacketThe Protocol Data Unit at Layer 3. It contains an IP header (source and destination IP addresses, TTL) with the transport segment as its payload.
PAMPrivileged Access Management. Tools and policies that control, monitor and audit elevated access to critical systems and accounts.
Patch PanelA passive Layer 1 device that provides a central termination point for network cables, so that structured cabling can be cross-connected to active equipment in an orderly way.
PDUProtocol Data Unit. The name for a unit of data at each OSI layer: data (L7 to L5), segment (L4), packet (L3), frame (L2), bits (L1).

PingA diagnostic tool that sends ICMP Echo Request packets to a target and measures the round-trip time. Used to check reachability and measure latency.
POP3Post Office Protocol version 3. Retrieves email by downloading messages from the server to one device. TCP port 110, or 995 over TLS. Less flexible than IMAP.
PortA 16-bit number (0 to 65535) at Layer 4 that identifies a service or application on a host. Ports 0 to 1023 are the system (well-known) ports. See Ports.
PPTPPoint-to-Point Tunneling Protocol. A legacy VPN protocol that tunnels PPP frames through an IP network inside GRE, with a control connection on TCP port 1723. It is regarded as insecure because of weak encryption; IPsec with IKEv2, or WireGuard, is used in its place.
Proxy ServerAn intermediary that handles requests between clients and servers, providing caching, filtering, access control and some anonymity. See Devices.
QoSQuality of Service. Techniques that give some kinds of traffic, such as voice and video, priority over others to protect their performance.
QUIC / HTTP/3QUIC is a transport protocol carried in UDP, with the TLS 1.3 handshake built in. HTTP/3 is HTTP running over QUIC, normally on UDP port 443. See Core Protocols.
RADIUSRemote Authentication Dial-In User Service. The protocol with which switches, wireless controllers and VPN gateways ask a central server to authenticate users and devices and to record their sessions. UDP ports 1812 (authentication) and 1813 (accounting). The usual back end for 802.1X.
RBACRole-Based Access Control. Grants permissions according to a person's role in the organisation, not to each individual separately.
RDPRemote Desktop Protocol. Provides graphical remote access to Windows systems on TCP port 3389. A frequent attack target when exposed to the internet.
RepeaterA Layer 1 device that regenerates an electrical or optical signal to extend the reach of a network segment. It does not inspect the data.
RiskA measure of how far something of value is threatened by a possible event: a function of the likelihood that a threat exploits a vulnerability and of the impact if it does (NIST SP 800-30 Rev. 1). It is not simply threat plus vulnerability. See Threats and Controls.
RouterA Layer 3 device that forwards packets between networks, using IP addresses and a routing table. See Devices.
RPCRemote Procedure Call. A way for a program to run a procedure on another system as if it were local, usually placed at Layer 5. Microsoft RPC uses an endpoint mapper on TCP port 135 to tell clients which port a service is on.
RPKIResource Public Key Infrastructure. Lets the holder of IP address space publish signed statements of which autonomous systems may originate its prefixes. Routers can then reject BGP announcements from the wrong origin (route origin validation).
SCTPStream Control Transmission Protocol. A connection-oriented Layer 4 protocol that sets up with a four-way handshake, supports several streams and several network paths per connection, and preserves message boundaries. Used in telecom signalling and for WebRTC data channels.
SegmentThe Protocol Data Unit at Layer 4 for TCP. It contains the transport header (source and destination ports, sequence number, flags) with the application data as its payload. A UDP unit is called a datagram.
SIEMSecurity Information and Event Management. A platform that collects logs from many sources, correlates events and raises security alerts. See Devices.
SIPSession Initiation Protocol. Sets up, manages and ends voice and video sessions; the basis of most VoIP systems. Port 5060, or 5061 over TLS.
SLAACStateless Address Autoconfiguration. The way an IPv6 host builds its own address from router advertisements, without a DHCP server.
SMBServer Message Block. The Windows file and printer sharing protocol, running over TCP port 445. It should not be reachable from the internet.
SMTPSimple Mail Transfer Protocol. Sends email between mail servers on TCP port 25. Mail clients submit outgoing mail on port 587.
SNMPSimple Network Management Protocol. Monitors and manages network devices. SNMPv3 adds encryption and authentication. UDP ports 161 and 162.
SocketA communication endpoint defined by an IP address, a port number and a protocol, for example TCP 192.168.1.1:443.
SQL InjectionAn application-layer attack in which SQL statements are inserted through input fields to read or change data in the back-end database. Prevented with parameterised queries and input validation, with a WAF as a second line of defence.
SSHSecure Shell. Provides encrypted remote command-line access and secure file transfer (SFTP, SCP). TCP port 22.
SSL / TLSSecure Sockets Layer / Transport Layer Security. Cryptographic protocols that give network communication encryption, integrity and authentication. TLS has replaced SSL. TLS 1.0 and 1.1 are deprecated; use TLS 1.2 or 1.3.
STPSpanning Tree Protocol. A Layer 2 protocol that prevents loops in switched networks by blocking redundant paths. Variants include RSTP and MSTP.
SubnetA logical subdivision of an IP network, defined by a subnet mask that separates the network part of an address from the host part. See Subnetting.
SwitchA Layer 2 device that forwards frames within a local network using a table of MAC addresses. A Layer 3 switch can also route. See Devices.
SyslogA standard protocol for sending log messages to a central server for storage, analysis and alerting. UDP port 514, or TCP port 6514 over TLS.
TCPTransmission Control Protocol. A connection-oriented, reliable Layer 4 protocol that uses sequence numbers, acknowledgements and retransmission. Its header is at least 20 bytes. See Key Comparisons.
TCP/IP ModelA 4-layer practical protocol model (Application, Transport, Internet, Network Access) on which modern networks and the internet run. See TCP/IP Architecture.
TelnetA legacy protocol for remote command-line access on TCP port 23. It sends everything, including passwords, in plaintext and has been replaced by SSH.
TFTPTrivial File Transfer Protocol. A simple file transfer protocol with no authentication or encryption, on UDP port 69. Used for network boot (PXE), firmware updates and device configuration.
ThreatAny potential cause of harm to a system or network. It may be human, technical, environmental or operational. See Threats and Controls.
Threat ActorA person or group able to carry out a threat: cybercriminals, state-backed operators, insiders, hacktivists. See Threats and Controls.
ThroughputThe amount of data actually transferred over a network in a given time. Bandwidth is the theoretical maximum; throughput is what remains after latency, packet loss, protocol overhead and congestion.
TLS HandshakeThe exchange in which client and server agree cipher suites, the server presents its certificate, and both derive the session keys, before encrypted communication begins.
TracerouteA diagnostic tool that traces the path packets take by sending probes with increasing TTL values. It shows each hop and its round-trip time. Uses ICMP or UDP.
TransceiverA Layer 1 device that both transmits and receives signals. In networking it usually means an SFP or SFP+ module that converts between electrical and optical signals.
TTLTime to Live. A field in the IPv4 header that every router decrements; a packet whose TTL reaches zero is dropped, which stops routing loops from running for ever. IPv6 calls the field Hop Limit.
UDPUser Datagram Protocol. A connectionless, lightweight Layer 4 protocol with no delivery guarantee and a fixed 8-byte header. Used for DNS, VoIP, streaming and QUIC. See Key Comparisons.
UnicastA one-to-one transmission from a single source to a single destination, the most common kind on IP networks. Compare broadcast (one to all), multicast (one to a group) and anycast (one to the nearest).
uRPFUnicast Reverse Path Forwarding. A router feature that, in strict mode, drops a packet when the route back to its source address does not lead out of the interface it arrived on. A defence against spoofed source addresses.
VLANVirtual LAN. Divides a physical switch into separate broadcast domains, which improves both security and performance.
VPNVirtual Private Network. Creates an encrypted tunnel over an untrusted network, usually the internet, for remote access or site-to-site connectivity. See Devices.
VulnerabilityA weakness in software, configuration, process or design that a threat can exploit. A vulnerability alone is not a risk: see Risk. See Threats and Controls.
WAFWeb Application Firewall. Inspects HTTP and HTTPS traffic at Layer 7 to block application-layer attacks such as SQL injection, XSS and CSRF. See Devices.
Wi-FiWireless LAN technology based on the IEEE 802.11 standards. Its security depends on WPA3 or WPA2 encryption, on authentication (802.1X or a pre-shared key) and on network segmentation.
Wireless APWireless Access Point. A Layer 2 device that bridges wireless clients onto a wired network. It advertises the network name (SSID) and manages radio channels and power.
XSSCross-Site Scripting. An application-layer attack in which malicious script is injected into web pages that other users view. The types are stored, reflected and DOM-based XSS. Mitigated with output encoding, a Content Security Policy and input validation.
Zero TrustA security approach in which no user or device is trusted because of where it sits on the network: every access request is checked against identity, device state, context and policy (NIST SP 800-207). See Layered Defence.
