Why This Matters

The Problem

Enterprise data is scattered, siloed and often ungoverned, so much of what an organisation collects is never put to use.

!
Data Silos
ERP, CRM, IoT, cloud applications and legacy systems operate in isolation. With no single source of truth, teams produce conflicting reports and duplicate each other's work.
!
Quality Crisis
Gartner states that "poor data quality costs organizations at least $12.9 million a year on average", citing its own research from 2020 (Gartner, Data Quality). Inconsistent formats, missing values and stale data erode trust in analytics.
!
Governance Gaps
Regulations such as GDPR, CCPA, India's DPDP Act and HIPAA demand strict control of personal data. Without governance, compliance risk grows and audits fail.
!
Wasted Potential
Seagate's Rethink Data report (2020), based on an IDC survey of 1,500 enterprise leaders that Seagate commissioned, found that 68% of the data available to enterprises goes unused (Seagate, July 2020). It is a vendor-commissioned survey, so treat the figure as an indication. Shadow IT and untracked data use add blind spots in decision-making.
💡 The Solution

What if one intelligent layer sat across your entire data estate, cataloguing, governing, monitoring quality and tracing lineage automatically? That is the Data Intelligence Layer.

Architecture

The 5-Layer Architecture

Data flows upward from sources (L1) through processing (L2) and storage (L3) to consumers (L5). The Data Intelligence Layer is numbered L4 in this guide, but data does not pass through it. It is a control plane that sits across the other four: it reads metadata from each and applies catalogue, quality, lineage and governance to all of them.

Architecture Approaches

Data Mesh and Data Fabric

Neither is a layer, and neither is a storage technology. Each is a way of organising the whole stack: data mesh changes who owns the data, data fabric changes how it is connected.

DM
Data Mesh
An operating and ownership model, not a product. Responsibility for analytical data moves from one central team to the business domains that know the data best, and each domain publishes it as a product for others to use. Zhamak Dehghani introduced the idea in 2019 and set out four principles in 2020:
  • Domain-oriented decentralised data ownership and architecture
  • Data as a product
  • Self-serve data infrastructure as a platform
  • Federated computational governance

Data contracts and SLAs between producer and consumer are a common way to put "data as a product" into practice. They are not a fifth principle.

DF
Data Fabric
A design concept for data management and data integration, not a product. A fabric takes in metadata from the systems an organisation already runs, analyses it, and uses the result to recommend or automate how data from dispersed sources is integrated and delivered (definition after Gartner).
  • Metadata collected from participating systems and users
  • Active metadata: analysed continuously, not just stored
  • Recommendations and automation for data integration
  • Often uses a knowledge graph to relate data assets
  • Builds on existing platforms instead of replacing them

Not to be confused with Microsoft Fabric, which is a product: a SaaS analytics platform built on a shared data lake (OneLake). It shares the word, not the definition.

How they relate to the layers

Mesh and fabric are not rivals, and neither replaces a storage choice in Layer 3. Mesh is about people and ownership; fabric is about metadata and automation. An organisation can apply either or both on top of a warehouse, a lake or a lakehouse. Both depend on the Data Intelligence Layer: a mesh needs a catalogue, quality rules and federated governance to make its data products discoverable and trustworthy, and a fabric is built from the same metadata and lineage.

Layer 3

Data Storage

Where data rests once it has been processed. Three storage patterns are in common use, and the lakehouse combines the other two.

DW
Data Warehouse
A database built for analytics. Data is structured and modelled before it is loaded (schema on write), so queries and reports are fast and consistent.
  • Structured, modelled tables
  • SQL as the main interface
  • Strong consistency and access control
  • Suited to BI and reporting
DL
Data Lake
Low-cost object storage that keeps files of any type in their original form. Structure is applied when the data is read (schema on read).
  • Structured, semi-structured and unstructured data
  • Open file formats such as Parquet, Avro and JSON
  • Storage scaled separately from compute
  • Needs a catalogue and governance to stay usable
LH
Data Lakehouse
Combines the flexibility of a data lake with the reliability of a data warehouse, on the same open storage.
  • ACID transactions on object storage
  • Open table formats: Delta Lake, Apache Iceberg, Apache Hudi
  • Schema enforcement & evolution
  • Time travel & version history
  • Unified batch + streaming support
Medallion Architecture (Bronze → Silver → Gold)

Bronze (raw): ingested as-is from source systems. Silver (cleaned): validated, deduplicated, and conformed. Gold (business-ready): aggregated, enriched, and optimised for consumption. Databricks and Microsoft Fabric both document this pattern for their lakehouses.

DatabricksMicrosoft FabricSnowflakeGoogle Cloud Lakehouse (was BigLake)

Data mesh and data fabric are not storage patterns. They are covered under Mesh & Fabric.

Layer 4: Core

The Data Intelligence Layer

The brain of the data estate. It does not store or move the data: it holds the metadata about it and applies the rules. Four pillars are its foundation.

C
Data Catalogue
Metadata Discovery: automatically crawl and index datasets across all sources.
Search & Browse: Google-like search for datasets, tables, dashboards.
Business Glossary: standardised definitions, owners, and stewards.
Tags & Classification: PII detection, sensitivity labels, domain tagging.
Data Products: package datasets with documentation, SLAs, and contracts.
Q
Data Quality
Profiling & Rules: automated statistical profiling, custom validation rules.
Anomaly Detection: ML-based detection of distribution shifts and outliers.
Freshness Monitoring: SLA tracking for data timeliness and staleness alerts.
Completeness & Accuracy: null checks, referential integrity, cross-source validation.
Data Contracts: schema and quality guarantees between producer and consumer.
L
Data Lineage
End-to-End Tracking: trace data from source to dashboard through every transformation.
Impact Analysis: understand downstream effects before making changes.
Column-Level Lineage: granular field-level tracking across pipelines.
Visual Flow Maps: interactive DAGs showing data dependencies.
Root Cause Analysis: quickly trace data issues back to origin.
G
Governance
Access Control (RBAC/ABAC): role and attribute-based fine-grained permissions.
Privacy & Masking: dynamic masking, tokenisation, and anonymisation.
Retention Policies: automated lifecycle management and data deletion.
Audit Trails: complete history of who accessed what, when, and why.
Regulatory Compliance: GDPR, CCPA, India's DPDP Act, HIPAA and SOX.
Master Data Management (MDM)

MDM ensures that critical business entities (customers, products, suppliers, locations) have a single, consistent, authoritative definition across the enterprise. MDM feeds into the catalogue (golden records), quality (matching & dedup), and governance (ownership & stewardship).

Key Capabilities
Golden record creation, entity resolution, match & merge, hierarchy management, reference data management
Example Tools
Informatica MDM, Reltio, Profisee, Semarchy, SAP Master Data Governance, EBX (formerly TIBCO EBX)

Adoption Roadmap

Data Intelligence Maturity Model

Where is your organisation on the journey? This four-level model is my own working model, not an industry standard. For a formal assessment, use a published framework such as DCAM (see Takeaways).

1
Reactive
Manual processes. No catalogue. Tribal knowledge. Data quality is an afterthought. Governance is spreadsheet-based.
2
Managed
Basic catalogue deployed. Some quality rules in place. Lineage tracked for critical pipelines. Initial governance policies defined.
3
Proactive
Automated quality monitoring. Full lineage coverage. Self-service catalogue widely adopted. Data stewards active. Observability dashboards live.
4
Intelligent
AI-augmented classification. GenAI-powered querying. Predictive quality. Automated governance. Data mesh with contracts. Full FinOps integration.
Summary

Key Takeaways

  • Centralised metadata & catalogue for discoverability
  • Automated data quality checks at every stage
  • End-to-end data lineage from source to dashboard
  • Unified governance framework (RBAC, masking, audit)
  • AI/GenAI-powered insights, agents, and automation
  • Self-service data democratisation via semantic layer
  • Cost optimisation, observability, and FinOps
  • Reverse ETL closes the operational loop
  • Open standards ensure vendor-agnostic portability
  • Data contracts formalise producer-consumer trust
Data Intelligence Layer =
The Brain of Modern Data Architecture

It's not a single tool: it's an architectural layer that combines catalogue, quality, lineage, governance, observability, and AI into a unified control plane over your entire data estate.

Without it, your Lakehouse is a data swamp. Your Data Mesh is a data mess. Your Fabric is just fabric.

Start with catalogue. Add quality. Then lineage. Then governance. Then AI. Build incrementally.

Industry Frameworks & Standards

Published frameworks that cover this ground in depth and are worth knowing:

  • DAMA-DMBOK (Data Management Body of Knowledge): the reference from DAMA International for the knowledge areas of data management, including governance, quality, metadata and master data. The second edition was revised in 2024 and a third is in preparation (DAMA).
  • TOGAF / Zachman: enterprise architecture frameworks that provide the structural context for where the Data Intelligence Layer fits within broader IT architecture.
  • DCAM (Data Management Capability Assessment Model): a framework from the EDM Council for assessing how capable an organisation's data management is (EDM Council).
