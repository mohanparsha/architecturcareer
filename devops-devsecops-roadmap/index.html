What changed in version 3.0. The AWS free-tier terms, the free labs, every outbound link and each change listed here were checked against the official source on 18 November 2026. The changes that affect what you do:
  • AWS Free Tier: accounts created from 15 July 2025 get credits and a six-month free plan, not 12 months of free use. Read How not to get billed before you open a cloud account (AWS Free Tier).
  • Browser labs: Play with Docker and Play with Kubernetes are removed. Docker's notice on both sites says they are unavailable from 1 March 2026. Killercoda and iximiuz Labs are the free labs listed now.

  • Kubernetes traffic routing: the ingress-nginx controller was retired in March 2026 and the Ingress API is frozen. Kubernetes recommends Gateway API for new work (retirement notice, Ingress documentation).
  • Licences and names: Vault and Terraform are under the Business Source License, which HashiCorp announced on 10 August 2023, so they are no longer open source (announcement). ZAP has been "ZAP by Checkmarx" since September 2024 and no longer carries the OWASP name (ZAP blog).
  • Supply chain: in March 2026 attackers replaced the version tags of the Trivy GitHub Actions with malicious code. Pin every third-party action to a full commit SHA (Trivy advisory).

⚡ What is DevOps?

The culture, practices, and tools that unite Development and Operations

DevOps is a set of cultural philosophies, practices, and tools that combines software development (Dev) and IT operations (Ops). The goal is to shorten the software development lifecycle and deliver high-quality software continuously. It is not a job title, a single tool, or a technology. It is a mindset and a way of working.

Traditionally, developers would write code and hand it off to a separate operations team to deploy. This created silos, communication gaps, and slow release cycles. DevOps eliminates these silos by encouraging teams to work together throughout the entire lifecycle, from planning and coding to testing, deployment, and monitoring.

Core Principles

🤝 Collaboration

Breaking down silos between development and operations teams.

🤖 Automation

Automating testing, deployment, and infrastructure provisioning to reduce human error.

🔄 CI/CD

Continuous Integration merges code frequently; Continuous Delivery/Deployment automates releases.

📊 Monitoring & Feedback

Continuously monitoring production systems and using feedback loops to improve.

📝 Infrastructure as Code

Managing infrastructure through code rather than manual processes.

🛡️ Security Integration

Embedding security checks throughout the pipeline, not just at the end.

🛡️ What is DevSecOps?

Security integrated into every phase of the software development lifecycle

DevSecOps extends the DevOps philosophy by integrating security practices into every phase of the development lifecycle, rather than treating security as a separate, final step. The traditional "security gate" model, where vulnerabilities discovered late were expensive to fix, is replaced by "shifting security left".

SAST Static Analysis

Scan source code for vulnerabilities before deployment (Semgrep, SonarQube)

DAST Dynamic Testing

Test running applications for vulnerabilities at runtime (ZAP, Nuclei)

SCA Composition Analysis

Scan dependencies and container images for known CVEs (Trivy, Grype)

IaC Scan Infra Security

Detect IaC misconfigurations before deployment (Checkov, Trivy)

Secrets Detection

Prevent hardcoded secrets from reaching repos (Gitleaks, TruffleHog)

IAM Access Control

Manage secrets and access with HashiCorp Vault or OpenBao, and Kubernetes RBAC

Related guide: the Secure SDLC guide on this site goes through the security activities stage by stage. This page stays with the DevOps toolchain and the learning plan.

How to read this: Code flows left to right through the pipeline. Each stage has tools you will learn in this roadmap. Security starts before the pipeline: Gitleaks checks every commit for secrets on your own machine, and again in CI. Semgrep, Trivy and ZAP then run in the Test stage. This is what makes it DevSecOps, not just DevOps. The pipeline is a continuous loop: Monitor feeds back into Plan.
♻️ Continuous Integration (CI)

Code → Build → Test: Every code change is automatically built and tested. Catches bugs early before they reach production.

🚀 Continuous Delivery/Deployment (CD)

Release → Deploy: Automatically prepare releases (delivery) or deploy directly to production (deployment). Reduces manual handoffs.

🛡️ Shift-Left Security

Code → Test: Security scanning runs automatically, as early as it can: secrets detection on every commit, SAST on code, SCA on dependencies, DAST on running apps.

📊 Observability Loop

Monitor → Plan: Metrics, logs, and alerts from production feed back into planning. SLIs/SLOs track reliability. Incidents drive improvements.

🧱 Prerequisites & Setup

What you need before starting your DevOps journey

Hardware Requirements

  • 8 GB RAM
  • Intel i5 / AMD Ryzen 5
  • 256 GB SSD (50 GB free)
  • Stable internet connection
🚀 Recommended Specs
  • 16 GB RAM
  • Intel i7 / AMD Ryzen 7
  • 512 GB SSD
  • Broadband connection
Low-spec machines: If you have only 8 GB RAM, close unnecessary apps when running containers and use a free browser lab for heavier workloads: Killercoda (free with registration; each scenario runs for up to one hour) or iximiuz Labs (free Basic plan: one playground at a time, one hour a day, no card needed).   • Ubuntu LTS (24.04 or 26.04), as dual-boot or inside VirtualBox/VMware

🔨 Projects Lab

20 hands-on projects from basic to expert: build your portfolio progressively

How to use this: Start with Basic projects during Phases 1–2. Move to Intermediate during Phases 3–4. Tackle Advanced during Phases 4–5. Expert projects are capstone-level for Phase 6 and beyond. Each project builds on skills from the previous tier. Push every project to GitHub with a detailed README, architecture diagram, and setup instructions.
How not to get billed. Read this before you open a cloud account. Projects 1 to 7, 9, 11 to 15, 18 and 20 can be done on your own machine and cost nothing. Projects 8, 10, 16, 17 and 19 use AWS services that are billed; each is marked below with a free or local way to practise the same skill. AWS terms below were read on aws.amazon.com/free and its FAQ on 18 November 2026; they change, so read them again on the day you sign up.
  • Know which plan you are on. A new AWS customer gets USD 100 in credits at sign-up and can earn up to USD 100 more by completing set activities. You choose a free plan or a paid plan. On the free plan you are not charged. It ends after six months or when the credits are used up, whichever comes first; AWS then closes the account unless you upgrade (its FAQ gives 90 days before the content is erased). The free plan does not include every service. On the paid plan, or once you upgrade, anything beyond your credits is charged at normal rates. The older offer of 12 months of limited free use applies only to accounts created before 15 July 2025.
  • Set a budget alert on day one. Create a monthly cost budget in AWS Budgets with an email alert at a small amount. An alert does not stop spending by itself, and AWS says budget figures are updated up to three times a day, so a warning can arrive hours after the charge.
  • Delete, do not just stop. Finish a cloud lab in one sitting, then delete what you created: run terraform destroy, and check in the console that EKS clusters, NAT gateways, load balancers, RDS databases, snapshots and public IPv4 addresses are gone. Most of these are billed for every hour they exist, whether or not you use them. Look at the Billing page again the next day.
  • Never commit keys. Do not create access keys for the root user, turn on MFA, and prefer temporary credentials (AWS root user best practices). Keep .env, *.tfvars and *.tfstate files out of Git with .gitignore, and run Gitleaks as a pre-commit hook. Anyone who finds a leaked key can create resources that are billed to you. If a key ever reaches a repository, delete the key in IAM straight away; deleting the commit is not enough.
  • Stay local when you can. kind and minikube run Kubernetes on your laptop for free. Moto (open source) can stand in for many AWS APIs in its server mode. LocalStack has needed an account and an auth token since 23 March 2026; its Hobby plan is free for non-commercial use (LocalStack notice).
  • Other clouds: the same rules apply on Azure, Google Cloud or any other provider. Free offers change, so read the provider's own page before you enter a card number.

Build an automated compliance checking system: Checkov scans IaC for CIS/PCI-DSS violations, Prowler audits live AWS accounts, OPA (Open Policy Agent) enforces K8s admission policies. Aggregate results into a Grafana dashboard showing compliance posture across all environments with pass/fail trends over time.

⚠️ Common Beginner Mistakes

Pitfalls that delay progress, and what to do instead

❌ Skipping Linux Fundamentals

Jumping straight to Docker or Kubernetes without understanding Linux commands, file permissions, and processes. Every DevOps tool runs on Linux.

✅ Spend the full 2 months on Phase 1. Do everything in the terminal.
❌ Learning Tools Before Concepts

Memorising Jenkins pipeline syntax without understanding what CI/CD is, or learning Terraform commands without understanding infrastructure.

✅ Always understand the "why" before the "how". Read the concept, then use the tool.
❌ Tutorial Hell: Watching, Not Building

Watching 50 hours of YouTube tutorials without building a single project. Passive learning creates an illusion of competence.

✅ For every hour of watching, spend 2 hours building. Every phase has a milestone: build it.
❌ Chasing Every New Tool

Trying to learn Docker, Kubernetes, Terraform, Ansible, Jenkins, ArgoCD, Prometheus, and 10 more tools simultaneously.

✅ Follow the phased roadmap. Master one tool per category before exploring alternatives.
❌ Ignoring Documentation Skills

Building projects but not writing README files, architecture diagrams, or documenting decisions. Employers check your GitHub profile.

✅ Document every project with a clear README, architecture diagram, and setup instructions.
❌ Not Using Git for Everything

Writing scripts, configs, and notes locally without version control. Losing work. Not building a GitHub history.

✅ From Day 1, push every script, config file, and exercise to a GitHub repo.
❌ Prioritising Certs Over Projects

Spending months preparing for certifications without building hands-on projects. Certs validate skills; they don't create them.

✅ Build projects first. Pursue certifications after completing the relevant phase.
❌ Studying in Isolation

Not joining communities, not asking questions, not sharing progress. The DevOps field is highly collaborative.

✅ Join communities from Day 1. Ask questions. Share what you learn. Help others.
❌ Leaving Cloud Resources Running

Creating a Kubernetes cluster, a NAT gateway or a database for a tutorial and forgetting it. Most cloud resources are billed for every hour they exist, used or not.

✅ Set a budget alert first, delete everything the same day, and read How not to get billed.

🎯 Interview Preparation

10 topic areas commonly tested in DevOps interviews

🐧 Linux & OS

File permissions, process management, systemd, cron, disk management, shell scripting problems

🌐 Networking

TCP vs UDP, DNS resolution, HTTP status codes, SSL/TLS handshake, subnetting

📦 Git

Merge vs rebase, conflict resolution, branching strategies (GitFlow, trunk-based), reverting

🐳 Docker

Images vs containers, multi-stage builds, networking modes, Compose, Dockerfile optimisation

☸️ Kubernetes

Pod lifecycle, Deployment vs StatefulSet, Services, Ingress and Gateway API, ConfigMaps, resource limits, probes

🔄 CI/CD

Pipeline design, delivery vs deployment, secrets handling, rollback strategies, artifacts

☁️ Cloud (AWS)

VPC design, security groups vs NACLs, S3 classes, EC2 types, IAM best practices

📝 Terraform & IaC

State management and locking, modules, Terraform vs Ansible, drift handling, remote backends

📊 Monitoring

Metrics selection, monitoring vs observability, alerting, SLIs/SLOs/SLAs, incident response

🛡️ Security & DevSecOps

OWASP Top 10, container security, SAST vs DAST, secret management, least privilege

📖 Glossary of Terms

91 DevOps & DevSecOps terms defined, organised by category for quick reference

Core DevOps Concepts
DevOpsCulture and practices combining Development and Operations for faster, reliable software delivery
DevSecOpsDevOps with security integrated into every phase of the development lifecycle ("shift-left security")
Shift LeftMoving testing and security earlier in the development process to catch issues sooner and cheaper
AutomationUsing scripts and tools to perform tasks without manual intervention, the core principle of DevOps
IdempotencyRunning an operation multiple times produces the same result, critical for Ansible, Terraform, and reliable automation
Immutable InfrastructureServers are never modified after deployment; changes require replacing with a new version entirely
Configuration DriftWhen a server's actual state diverges from its defined configuration. IaC tools prevent this
ToilManual, repetitive operational work that can and should be automated (SRE term)
CI/CD & Pipeline
CIContinuous Integration: automatically building and testing code every time a developer pushes changes
CD (Delivery)Continuous Delivery: code is automatically prepared for release but requires manual approval to deploy
CD (Deployment)Continuous Deployment: code is automatically deployed to production without manual approval
PipelineAutomated sequence of stages (build → test → deploy) that code passes through from commit to production
ArtifactA built output (Docker image, JAR, binary) produced by a CI pipeline and stored in a registry
GitOpsUsing Git as the single source of truth for infrastructure and deployments: changes via PRs, not manual commands
Blue/GreenDeployment strategy running two identical environments; traffic switches from old (blue) to new (green) for zero downtime
Canary DeployGradually routing a small percentage of traffic to a new version before full rollout
RollbackReverting to a previous known-good version when a deployment fails or causes issues
Containerisation & Orchestration
ContainerLightweight, isolated package containing an application and all its dependencies, so it runs identically everywhere
Docker ImageRead-only template used to create containers, built from a Dockerfile as a stack of filesystem layers
DockerfileText file with instructions to build a Docker image; it defines the base image, dependencies, and startup command
Docker ComposeTool for defining and running multi-container applications using a YAML configuration file
Container RegistryStorage for Docker images (Docker Hub, AWS ECR, GHCR), like GitHub but for container images
Kubernetes (K8s)Open-source container orchestration platform that automates deployment, scaling, and management of containers
PodSmallest deployable unit in Kubernetes: one or more containers that share networking and storage
DeploymentK8s object that manages a set of identical Pods and handles scaling, updates, and rollbacks
ServiceK8s object that exposes Pods to network traffic and gives a group of Pods a stable IP and DNS name
IngressK8s object that manages external HTTP/HTTPS access to Services (routing, TLS, load balancing). The API is frozen: it still works and will not be removed, but new features go into Gateway API
Gateway APIThe Kubernetes project's recommended replacement for Ingress when routing traffic into a cluster, built from GatewayClass, Gateway and HTTPRoute resources
HelmPackage manager for Kubernetes that bundles K8s manifests into reusable, versioned charts with configurable values
RBACRole-Based Access Control: restricts who can do what in Kubernetes (or any system) based on assigned roles
Cloud & Infrastructure
VPCVirtual Private Cloud: isolated network within a cloud provider where you launch resources (AWS, GCP, Azure)
EC2Elastic Compute Cloud: AWS virtual servers (instances) that you can start, stop, and scale on demand
S3Simple Storage Service: AWS object storage for files, backups, static assets, and Terraform state
IAMIdentity and Access Management: controls who can access what in AWS (users, roles, policies, permissions)
RDSRelational Database Service: managed database (PostgreSQL, MySQL) on AWS with automated backups and scaling
Auto ScalingAutomatically adjusting the number of running servers based on demand, scaling up under load and down when idle
Load BalancerDistributes incoming traffic across multiple servers to ensure availability and prevent overload (ALB, NLB)
Free TierAWS's offer for new customers. For accounts created from 15 July 2025: up to USD 200 in credits and a free plan that ends after six months or when the credits run out. It is not 12 months of free use: see How not to get billed
Infrastructure as Code (IaC)
IaCInfrastructure as Code: defining and provisioning infrastructure through code files instead of manual setup
TerraformIaC tool from HashiCorp (now part of IBM). It uses the HCL language to provision cloud infrastructure across AWS, GCP, Azure, and more
HCLHashiCorp Configuration Language: the declarative language used to write Terraform configurations
State FileTerraform's record of what infrastructure it has created. It maps your code to real cloud resources
State LockingStops two runs changing the same state at once. With the S3 backend, use its own lock file (use_lockfile); the DynamoDB lock table is deprecated
Terraform ModuleReusable, self-contained package of Terraform configurations, like a function for infrastructure
OpenTofuOpen-source fork of Terraform (Linux Foundation), created after HashiCorp changed Terraform's licence to the Business Source License (BSL) in 2023
AnsibleAgentless configuration management tool that uses YAML playbooks to configure servers via SSH
PlaybookAnsible YAML file defining tasks to execute on remote servers, the main unit of Ansible automation
Monitoring & Observability
ObservabilityAbility to understand a system's internal state from its external outputs: metrics, logs, and traces
PrometheusOpen-source metrics collection and alerting system that pulls metrics from targets at defined intervals
GrafanaVisualisation platform that creates dashboards from Prometheus, Loki, and other data sources
LokiLog aggregation system by Grafana Labs that indexes log labels, not content. Logs are sent to it by Grafana Alloy, which replaced Promtail (end of life 2 March 2026)
Grafana AlloyGrafana's telemetry collector, a distribution of the OpenTelemetry Collector. It is what ships logs to Loki now
PromQLPrometheus Query Language: used to query metrics and create alerting rules and dashboard panels
SLIService Level Indicator: a quantitative measure of service performance (e.g., request latency, error rate)
SLOService Level Objective: target value for an SLI (e.g., "99.9% of requests under 200ms")
SLAService Level Agreement: contractual commitment between provider and customer with consequences if not met
Error BudgetAmount of allowed unreliability (100% − SLO). When exhausted, new feature releases are frozen until reliability improves
AlertmanagerPrometheus component that handles alert routing, grouping, silencing, and notification (Slack, email, PagerDuty)
Security & DevSecOps
SASTStatic Application Security Testing: scans source code for vulnerabilities without running it (Semgrep, SonarQube)
DASTDynamic Application Security Testing: tests running applications for vulnerabilities at runtime (ZAP, Nuclei)
SCASoftware Composition Analysis: scans dependencies and container images for known CVEs (Trivy, Grype)
CVECommon Vulnerabilities and Exposures: standardised identifier for publicly known security vulnerabilities (e.g., CVE-2021-44228)
OWASP Top 10OWASP's awareness document listing the 10 most critical web application security risks, the baseline every developer should know. The current edition is 2025
Secrets ManagementSecurely storing and accessing credentials, API keys, and tokens. Never hardcode secrets: use a secrets manager such as Vault or OpenBao. Kubernetes Secrets are stored unencrypted in etcd by default (base64 is encoding, not encryption), so turn on encryption at rest and restrict access with RBAC
Least PrivilegeGranting only the minimum permissions needed to perform a task, a foundational security principle
Zero TrustSecurity model that trusts nothing by default: every request is verified regardless of origin or network location
OPAOpen Policy Agent: policy engine for enforcing rules across K8s, APIs, and infrastructure as code
CIS BenchmarksCenter for Internet Security best-practice configuration standards for operating systems, cloud, and applications
PCI-DSSPayment Card Industry Data Security Standard: compliance framework for organisations handling credit card data
Networking
OSI Model7-layer conceptual model for network communication: Physical, Data Link, Network, Transport, Session, Presentation, Application
TCP/IPTransmission Control Protocol / Internet Protocol: the fundamental communication protocols of the internet
DNSDomain Name System: translates human-readable domain names (www.example.com) into IP addresses (such as 192.0.2.10)
CIDRClassless Inter-Domain Routing: notation for IP address ranges (e.g., 10.0.0.0/16 = 65,536 addresses)
NATNetwork Address Translation: maps private IPs to public IPs, allowing internal servers to access the internet
Reverse ProxyServer that sits in front of backend servers and forwards client requests to them. Used for load balancing, TLS, and caching (Nginx)
SSL/TLSSecure Sockets Layer / Transport Layer Security: encrypts data in transit between client and server (HTTPS)
SubnetA segmented portion of a larger network, used in VPCs to isolate public-facing and private resources

For the layers and protocols in more depth, see the Network Concepts guide.

Version Control & Collaboration
GitDistributed version control system that tracks changes to files, enabling collaboration and history management
BranchIndependent line of development in Git that allows working on features without affecting the main codebase
Pull Request (PR)Request to merge changes from one branch into another; it includes code review, discussion, and approval
Merge vs RebaseMerge creates a commit joining two branches; Rebase rewrites history to place commits on top of another branch
GitFlowBranching strategy with dedicated branches for features, releases, and hotfixes: structured but heavyweight
Trunk-BasedBranching strategy where all developers commit to a single main branch with short-lived feature branches
Formats, Protocols & General
YAMLHuman-readable data format used for configuration files. Kubernetes, Docker Compose, Ansible, and CI/CD all use YAML
JSONJavaScript Object Notation: lightweight data format for APIs and configuration (parsed with jq on command line)
APIApplication Programming Interface: defined way for software components to communicate (REST APIs use HTTP)
RESTRepresentational State Transfer: architectural style for APIs using HTTP methods (GET, POST, PUT, DELETE)
SSHSecure Shell: encrypted protocol for remote server access and command execution (port 22)
HTTP/HTTPSHypertext Transfer Protocol (Secure): the protocol browsers use to communicate with web servers (port 80/443)
SRESite Reliability Engineering: discipline applying software engineering to operations problems (coined by Google)
Post-MortemBlameless analysis conducted after an incident that documents what happened, why, and how to prevent recurrence
